# Windows: запуск одной командой

Нужны Windows x64, установленный Docker Desktop с Linux containers / WSL 2 и интернет
для первого запуска. JDK 21, Maven и JavaFX-библиотеки скрипт подготовит автоматически.

1. Распакуйте **обновлённый** проект в обычную доступную для записи папку, например
   `C:\FixFlow`. Рядом со `start.cmd` должны находиться `compose.yaml`, `Dockerfile`,
   `pom.xml`, `mvnw.cmd`, папки `.mvn`, `scripts` и три Maven-модуля.
2. Откройте Docker Desktop.
3. Дважды нажмите `start.cmd`, либо в PowerShell в папке проекта выполните:

   ```powershell
   .\start.cmd
   ```

При первом запуске нужно дождаться загрузки образов, JDK и зависимостей. Скрипт:

- создаёт `.env` из `.env.example`, если файла ещё нет;
- запускает PostgreSQL и backend в Docker;
- ждёт готовности backend после миграций и seed;
- использует установленный JDK 21 либо скачивает официальный Temurin JDK 21,
  проверяет SHA-256 архива и сохраняет JDK в `.local/runtime/jdk-21`;
- устанавливает contracts/desktop через Maven Wrapper и открывает настоящее окно JavaFX.

Это один запуск для пользователя. Сервер и БД работают в Docker; графическое окно
JavaFX работает в Windows. Отдельный X-сервер, VNC или ручное скачивание JavaFX не нужны.
Запуск непосредственно `docker compose up` поднимает серверы; окно открывает `start.cmd`.
Программа установки `.exe` не создаётся.

По умолчанию в окне входа: сервер `http://127.0.0.1:8080`, email `owner@fixflow.test`,
пароль `Fictional-Demo-2026!`. Есть также `manager1@fixflow.test` и `tech1@fixflow.test`.
Скрипт выбирает адрес по опубликованному порту backend, поэтому изменение `SERVER_PORT`
в `.env` учитывается автоматически.

## Следующие запуски и остановка

Следующий запуск — снова `start.cmd`; образы, JDK и Maven-зависимости кешируются.
Если в старой копии уже создан контейнер PostgreSQL этого проекта, используется его
существующий том `fixflow_postgres_data`. Скрипт не перезаписывает существующий `.env`.

Чтобы остановить: закройте окно FixFlow, затем дважды нажмите `stop.cmd` или выполните:

```powershell
.\stop.cmd
```

Это выполняет `docker compose stop`. Том базы сохраняется. Demo-seed создаётся один раз,
повторный запуск не сбрасывает заказы и пароли. На новом компьютере с новой БД создаётся
новый demo-набор; собственные заказы переносятся отдельной резервной копией PostgreSQL.

## Только серверы

Для PostgreSQL и backend без окна и без JDK на Windows:

```powershell
.\start.cmd -ServicesOnly
```

Или на любой системе с Docker Compose:

```bash
docker compose up -d --build --wait --wait-timeout 240
```

Compose ожидает готовый PostgreSQL перед backend. Внутри сети backend использует
`postgres:5432`, независимо от опубликованного порта БД на компьютере. Backend слушает
внутри контейнера `0.0.0.0:8080`, наружу публикуется только localhost.
Проверка `/actuator/health/readiness` включает БД и состояние готовности Spring Boot;
запуск JavaFX не начинается при ошибке сборки или неготовом backend.

## Если запуск остановился с ошибкой

Консоль остаётся открытой с текстом ошибки. Проверьте Docker Desktop и его Linux engine.
Диагностика серверов из папки проекта:

```powershell
docker compose ps
docker compose logs --tail 80 backend
```

Если порт уже занят ранее запущенным локальным backend, остановите этот процесс или
выберите свободный `SERVER_PORT` в `.env`. Для занятого порта БД измените `POSTGRES_PORT`.
Пароль `.env` должен соответствовать существующей БД; смена значения файла не меняет
пароль пользователя уже созданного PostgreSQL.

При ошибке `Failed to validate Maven distribution SHA-256` на этапе Docker build
обновите проект: в исправленном `Dockerfile` установлен `unzip`. Без него Wrapper
скачивал TAR.GZ, хотя закреплённая контрольная сумма относится к ZIP. Повторите:

```powershell
docker compose build backend
.\start.cmd
```

Удалять том PostgreSQL или отключать проверку SHA-256 не требуется.

При ограниченном доступе к сервису JDK можно установить JDK 21 вручную, указать
`JAVA_HOME`, после чего повторить `start.cmd`. Системный JDK другой версии не удаляется.
Скрипты не меняют системные переменные окружения и не устанавливают глобальную политику
PowerShell; настройки действуют только в процессе запуска.

Dockerfile собирает backend на Java 21 через Wrapper и запускает JAR на JRE 21
с непривилегированным UID 10001. Локальные `.env`, `.local` и `target` исключены из
Docker-контекста. Контейнерная сборка пропускает тесты; полный `verify` и отдельные
проверки Docker/PowerShell заданы в CI. Их фактический статус — в
[IMPLEMENTATION_STATUS.md](../IMPLEMENTATION_STATUS.md).
