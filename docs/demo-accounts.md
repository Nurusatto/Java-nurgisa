# Демонстрационные учётные записи

Только вымышленные локальные аккаунты. Создаются при `SPRING_PROFILES_ACTIVE=dev`,
`FIXFLOW_DEMO_ENABLED=true` и явно заданном `FIXFLOW_DEMO_PASSWORD` (минимум 10 символов, максимум 72 байта UTF-8).
При профиле `prod` демонстрационные компоненты не регистрируются.

| Роль | Email |
| --- | --- |
| Владелец | `owner@fixflow.test` |
| Администраторы | `manager1@fixflow.test`, `manager2@fixflow.test` |
| Мастера | `tech1@fixflow.test` … `tech5@fixflow.test` |

Фиктивный пароль из `.env.example`: `Fictional-Demo-2026!`.
В БД сохраняются только BCrypt-хеши. При повторном запуске пароль не сбрасывается.
Эти значения нельзя использовать для реальных аккаунтов.

Первый dev-запуск создаёт сотрудников и набор `workshop-v1`: 30 клиентов,
60 устройств, 80 заказов во всех десяти статусах, 72 диагностики и 122 работы,
40 запчастей, 5 поставщиков, 10 закупок, 60 платежей, 25 расходов, 24 гарантии,
возврат, уведомления и аудит. Даты строятся относительно первого запуска.

При первом заполнении до фиксации транзакции проверяются минимальные количества,
остатки и стоимость склада, хронология движений, даты сотрудников, отсутствие двух
активных demo-ремонтов одного устройства, расчёты выданных заказов и гарантий.
Неисправности, работы и категории деталей согласованы с типами устройств.

Повторный запуск видит маркер версии и не загружает набор заново, не изменяет
созданные пользователем данные и не сбрасывает изменённые пароли.
Для ручного запуска seed запустите backend с тремя переменными из первого абзаца;
он заполнит новую базу автоматически после миграций.
Для новой демонстрации остановите backend и используйте
`scripts/dev-reset.sh --new-demo-database`: создаётся новая БД, старые данные
сохраняются, исходный `.env` копируется в игнорируемую `.local/reset-backups/`.
Скрипт требует Docker Compose; при локальном PostgreSQL создайте отдельную новую
БД через `createdb` и измените `POSTGRES_DB` в локальном `.env`.
