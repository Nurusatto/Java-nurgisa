# Проверки и стратегия тестирования

## Воспроизведение

```bash
./mvnw -B -ntp verify
```

Без внешних настроек интеграционные тесты запускают PostgreSQL 18.6 через
Testcontainers. Нужен доступный Docker daemon. Альтернатива — отдельная тестовая БД:

```bash
export FIXFLOW_TEST_DATABASE_URL=jdbc:postgresql://127.0.0.1:55432/fixflow_test
export FIXFLOW_TEST_DATABASE_USER=fixflow
export FIXFLOW_TEST_DATABASE_PASSWORD=local_test_only
./mvnw -B -ntp verify
```

Нельзя указывать пользовательскую рабочую БД. Тесты добавляют собственные UUID-фикстуры;
откат транзакции проверяется отдельно, общая очистка пользовательских данных не выполняется.
Surefire запускает unit-тесты, Failsafe — BackendApplicationIT с реальными HTTP/SQL.
Тесты не пропускаются автоматически при отсутствии Docker: нужно предоставить БД или
устранить ошибку окружения. H2 вместо PostgreSQL не используется.

## Что проверяется

- Контракты ошибок, разрешённые/запрещённые переходы ремонта, CSV и защита формул.
- Границы денежных сумм/количеств, переполнение экспоненциальной записи, дробная точность,
  ограничение BCrypt в байтах UTF-8 с сохранением пробелов пароля.
- Вход с CSRF, cookie/выход, отзыв сессий при смене пароля, сохранение пробелов пароля,
  ограничение попыток входа, проверки актуальной роли и отключённых сотрудников.
- Владелец устройства, назначение мастера, история, устаревшая версия и ошибки валидации.
- Полный расчёт ремонта, частичная оплата, запрет выдачи с долгом, выдача и гарантия,
  возврат сверх платежа, скидка отдельной корректировкой, согласованность отчётов.
- Гарантийное обращение после отключения прежнего мастера, бесплатная деталь с сохранением
  себестоимости, отзыв гарантии, отмена ремонта с контролируемым возвратом деталей и историей.
- Две одновременные попытки взять последнюю деталь: ровно одна успешна.
- Откат неудачной операции, отсутствие двойного списания, различие тела одного ключа,
  частичные поступления 3+2, запрет перепоступления, точность дробных возвратов.
- Приватность уведомлений, безопасная проекция tracking, хеш и отзыв ссылки.
- Пагинация после сортировки, безопасные поля сортировки, поиск кириллицы без учёта регистра,
  нормализованный телефон, неверные UUID/даты с ответом 400.
- Desktop: состояние списков, разбор ошибок/ответов API, недоступный сервер, FXML.

## Реальный интерфейс

После `verify`, `install`, запуска dev-backend и загрузки `.env`:

```bash
scripts/gui-smoke.sh
```

Нужен графический сеанс Linux/GTK 3 или X11. Сценарий запускает настоящий JavaFX,
открывает экраны, проверяет меню трёх ролей и проходит ремонт через формы и кнопки.
Он создаёт собственные записи с префиксом GUI Smoke, не удаляя ранее созданные данные.
Проверяет также ввод десятичной запятой, фильтры просрочки/остатков и сортировку платежей.
`FIXFLOW_GUI_SCREENSHOT=/tmp/dashboard.png` сохраняет снимок окна самого приложения.
Этот отдельный сценарий не входит в headless `verify`.

## Миграции и seed

На новой dev-базе запускается backend, проверяются шесть успешных миграций и маркеры
`identities-v1`, `workshop-v1`. SeedVerifier проверяет согласованность перед commit.
Для проверки повторяемости фиксируются количества сущностей, backend перезапускается,
после чего количества сравниваются. Изменённые пароли/данные не сбрасываются.

Отдельная пустая production-база проверяется с явным bootstrap первого OWNER и даже
включённым demo-флагом: сотрудников должен быть один, клиентов/заказов/seed-маркеров — ноль.

Фактические результаты последних запусков и непроверенные части окружения указаны
в [IMPLEMENTATION_STATUS.md](../IMPLEMENTATION_STATUS.md). Наличие CI workflow само по
себе не подтверждает прохождение GitHub Actions. Физическая печать требует отдельной
проверки с установленным принтером; HTTP-данные квитанции можно проверить без оборудования.

## Docker и Windows launcher

```bash
python3 test-scripts/wrapper-download.py
```

Три проверки запускают настоящий Wrapper с пустым кешем и локальными тестовыми архивами:
ZIP принимается при верной сумме; повреждённый ZIP и TAR.GZ с суммой ZIP отклоняются
до запуска Maven. В Docker build установлен `unzip`, чтобы Wrapper выбирал ZIP.

```bash
python3 test-scripts/start-linux.py
```

Восемь проверок Linux launcher с подменой команд: порядок Compose/readiness/install/окно,
остановка при ошибке, режимы отдельного клиента/серверов, JDK 21, сохранение `.env` и
чтение его значений без исполнения команд. Настоящее окно проверяется отдельно.

```powershell
pwsh -NoProfile -File test-scripts/start-windows.Tests.ps1
```

Одиннадцать проверок выполняют функции скрипта с подменой Docker/сети/запуска окна:
сохранение `.env`, опубликованный порт, ошибки команд, остановка без удаления томов,
порядок готовности сервисов/сборки desktop/открытия окна, запрет выполнения JDK при
неверной SHA-256 и установка проверенного архива с сохранением прежнего кеша.
При сбое Compose проверяются вывод статуса/логов, запрет запуска JavaFX и сохранение
исходной ошибки даже при недоступности диагностических команд.
Это не подменяет проверку настоящего окна на Windows.

```bash
python3 test-scripts/healthcheck.py
```

Три проверки компилируют Docker healthcheck на Java 21 и запускают его против настоящего
HTTP-сервера: 200, 503 и отсутствующий сервер. Backend IT дополнительно проверяет
анонимные readiness/liveness без раскрытия внутренних деталей.

В CI добавлены отдельные задания Windows PowerShell 5.1 и Docker smoke: сборка образа,
ожидание readiness, 80 заказов/8 аккаунтов после seed, перезапуск и отсутствие дублей.
Удалённые задания нужно фактически запустить, прежде чем считать их прошедшими.
